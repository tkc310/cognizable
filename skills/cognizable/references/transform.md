# 文書変換: 資料を4層の成果物にする

`/cognizable doc 対象` で使う。既存の資料を、1画面の要約から順に深掘りできる成果物に変換する。

成果物の既定の形式は HTML の1ページ。`assets/template.html` を元に作り、見た目は `references/design.md` に従う。HTML を出せない環境では、同じ4層を Markdown の見出しで作る。

対象がソースコードのときは、`references/code.md` も読む。

## 4層の構造

読む層は L0、L1、L2 の3つ。L3 は確認用の原典。層を5つ以上に増やさない。

| 層 | 役割 | 置くもの | 分量の目安 |
|----|------|----------|------------|
| L0 | 1画面の要約 | 結論、次の一手、全体の地図、主要な用語、各ブロックの所要時間 | スクロールなしの1画面 |
| L1 | ブロックごとの概要 | 主張を述べる見出し、論点、比較の表 | 1ブロックを2〜3分で読める長さ |
| L2 | 種類別の詳細 | 手順、参照、解説 | 必要な長さ。折りたたんで置く |
| L3 | 原典 | 元の資料の該当箇所へのリンク | リンクだけ |

### L0 に置くもの

L0 は常に表示する。折りたたまない。

1. 結論: 1〜2文。資料全体が何を言っているか。
2. 次の一手: 読み手が次にする行動を1つ。
3. 全体の地図: 図を1枚。3〜4ブロックで、流れは一方向にする。各ブロックは L1 の見出しへのリンクにする。
4. 主要な用語: 3〜5語。1語につき1行で定義する。
5. 所要時間: ブロックごとの読む時間を数字で書く。

### L1 に置くもの

L1 のブロックは3〜4個にする。5個以上になるときは、ブロックをまとめ直す。

1. 見出し: 主張を述べる文にする（R13）。
2. 論点: 3〜4点。論点どうしの関係を接続語か矢印で示す（R2）。
3. 比較: 選択肢や条件の比較があれば表にする（R8）。
4. L2 への入口: 折りたたみの見出しとして置く。見出しには、開くと何があるかを書く。

### L2 に置くもの

L2 は種類ごとに分ける（R15）。1つの折りたたみに1種類だけ入れる。

| 種類 | 形 | 見出しの書き方の例 |
|------|----|--------------------|
| 手順 | 番号付きリスト。1手順に1動作（R4） | 「手順: 本番に反映する（4手順、約10分）」 |
| 参照 | 表 | 「一覧: 設定値と既定値（12項目）」 |
| 解説 | 短い段落。1段落は3文まで | 「解説: なぜキャッシュを先に消すのか」 |

### L3 に置くもの

元の資料のページ、節、行へのリンクを置く。本文を写さない。リンクには、リンク先に何があるかを書く。

## 変換の手順

1. 目的を1つ決める。読み手が何を決めたいか、何をしたいかを確かめる。依頼から読み取れないときは、質問を1つだけする。
2. 抽出する。資料から主張、手順、参照データ、用語を拾う。拾った項目に、手順、参照、解説のどれかを付ける。
3. 削る。目的に無関係な内容を L3 に送る。捨てずに、リンクでたどれるようにする。
4. 群化する。残った内容を3〜4ブロックに分ける。ブロックごとに、主張を述べる見出しを付ける。
5. 図にする対象を選ぶ。分岐、依存関係、時系列だけを図にする。直線的な手順は番号付きリストにする。
6. 4層に配置する。L0 を最初に書く。次に L1、L2、L3 の順に書く。
7. 検査する。下の「渡す前の確認」を通す。

## 削ってよいものと、削らないもの

| 削る（L3 に送る） | 削らない |
|--------------------|----------|
| 目的に関係しない背景、経緯、謝辞 | 正確な用語と定義 |
| 同じ内容の繰り返し | 因果や条件を示す接続語 |
| 例が3つ以上あるときの、3つ目以降 | 数値、単位、固有名 |
| 装飾の図、雰囲気を出すための画像 | 例外と注意事項 |

語彙を平易な言葉に置き換えない。読み手の言語理解は高い。平易化で情報が落ちると、読み手は推測で補うことになる。

## 図の使い方

読み手は、空間的なイメージの保持が小さい。図は型を絞って使う。

- 使う型: 表、一方向の流れ図、浅い階層図（2段まで）。
- 避ける型: 矢印が交差する図、双方向の矢印が多い図、3段以上の入れ子。
- 1枚の図には、主張を1つだけ入れる。
- L0 の地図は3〜4ブロック。L1 と L2 の図は7〜9ノードから始める。超えるときは図を分ける。
- ラベルは図の中に直接書く。凡例を別の場所に置かない。
- 図の説明文は、図のすぐ隣に置く。

ノード数の目安は開始値。フィードバックの記録で調整する。

## 渡す前の確認

1. L0 だけを読んで、結論と次の一手が分かるか。
2. L1 の見出しだけを上から読んで、要旨が分かるか。
3. L0 と L1 に、4つを超える並列の項目がないか。
4. どの層からも、L0 の地図に戻るリンクがあるか。
5. 削った内容に、L3 からたどり着けるか。
6. 成果物が HTML で、cognizable のリポジトリが手元にあるとき、`python3 scripts/check.py 成果物.html` が通るか。

渡した直後に、SKILL.md の「読み手が言い出すのを待たない」の確認を1行出す。
