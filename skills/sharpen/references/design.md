# デザイン規則

`/sharpen doc` の成果物と、`/sharpen design 対象` で使う。日本語の HTML ページを前提にする。規則には D1 からの ID を振る。フィードバックで規則を指すときに使う。

`assets/template.html` は、D1〜D13 を満たすひな形。新しいページは、ひな形の CSS 変数と構造を変えずに、中身だけを入れ替えて作る。

数値は開始値。フィードバックの記録で調整する。根拠と証拠の強さは、リポジトリの `docs/evidence.md` にある。

## 規則

### D1. 本文の行長は全角30〜38字、最大40字

本文の幅を `max-width: 36em` にする。40em を超えない。表と図は、本文の幅を超えてよい。

### D2. 本文は16px以上、行の高さは1.7〜1.8

段落の間は、文字サイズの1〜2倍あける。字間を詰めない。1段落は3文までにする。行頭をそろえる。両端揃えにしない。

### D3. 書体はゴシック体1種と等幅1種

OS に入っている一般的なゴシック体を使う。ディスレクシア用の専用書体は使わない。メタ分析で効果が確認されていない。斜体を使わない。強調は太字にする。

### D4. コントラストは本文7:1以上、図の線と部品は3:1以上

背景と文字の色は、ひな形の変数を使う。薄い灰色の文字で補足を書かない。

### D5. 意味を持つ色は4色まで。意味を固定する

色に意味を持たせるときは、次の4つの中から使う。同じ色を別の意味に使わない。色だけで意味を伝えない。文字か形を必ず併用する。

| 変数 | 意味 | 併用する文字の例 |
|------|------|------------------|
| `--sem-now` | 現在地、選択中 | 「現在地」 |
| `--sem-act` | 次の一手、操作できる部品 | 「次の一手」 |
| `--sem-warn` | 注意、取り消せない操作 | 「注意」 |
| `--sem-ok` | 完了 | 「完了」 |

### D6. ライトを既定にし、ダークへ切り替えられるようにする

OS の設定に従う。ページ内の設定でも切り替えられるようにする。

### D7. 自動で動くものを置かない

自動再生、点滅、視差効果、装飾のアニメーションを使わない。動きは、読み手の操作への応答だけに使う。`prefers-reduced-motion` が指定されていれば、操作への応答の動きも止める。

### D8. 本文は1カラム。周辺に装飾を置かない

サイドバーに置いてよいのは目次だけ。広告枠、関連リンク、装飾の画像を本文の横に置かない。補足は、本文の流れの中に枠で置く。

### D9. 現在地を常に表示する

固定の目次を置く。目次の中で、今読んでいる節を強調する。強調には `--sem-now` と「現在地」の文字を使う。各ブロックの見出しの上に、「全4ブロック中の2」の形で位置を書く。

### D10. 折りたたむのは L2 と L3 だけ

結論、次の一手、L0、L1 は常に表示する。折りたたみには `<details>` を使う。

- 複数の折りたたみを同時に開けるようにする。1つを開いたときに、他を自動で閉じない。
- 「すべて開く」と「すべて閉じる」の操作を置く。
- 折りたたみの見出しに、開くと何があるかと、分量を書く。

### D11. 用語の定義をホバーだけにしない

主要な用語は、L0 の用語表に載せる。本文中の初出でも、文の中で説明する。ホバーでしか読めない説明を作らない。

### D12. 図は1枚に1つの主張。ラベルは図の中に書く

- 型は、表、一方向の流れ図、浅い階層図に絞る。
- L0 の地図は3〜4ブロック。他の図は7〜9ノードから始める。
- 矢印の向きを1つの図の中で混ぜない。左から右か、上から下のどちらかにする。
- 凡例を別に置かない。ラベルを図の中に直接書く。
- 図の説明文を、図のすぐ下に置く。
- 図は HTML と CSS、またはインラインの SVG で書く。画像ファイルにしない。文字を選択でき、拡大でき、テーマに従うため。

### D13. 設定は4つまで

読み手が変えられる設定は、テーマ、密度、文字サイズ、動きの4つにする。設定を増やさない。設定の操作自体が注意を奪う。

| 設定 | 選択肢 |
|------|--------|
| テーマ | 自動、ライト、ダーク |
| 密度 | 標準（L2 を閉じる）、詳細（L2 を開く） |
| 文字サイズ | 標準、大 |
| 動き | あり、なし |

## 規則に入れなかった通説

次の3つは、根拠が弱いか、否定されている。規則にしない。

- 「純白の背景は有害」: 成人での実証は見つかっていない。ひな形の背景は、好みの範囲としてわずかに色を付けている。
- 「ダークモードは読みやすい」: 一般の読み手では、明るい背景のほうが読みの成績がよい。
- 「シンタックスハイライトは理解を速める」: 初心者390名の実験で効果がなかった。使ってよいが、色数を D5 の範囲に抑える。

## `/sharpen design` の手順

既存のページや図を整えるときは、次の順で行う。

1. 対象を D1〜D13 と照らす。合わない規則の ID を一覧にする。
2. 一覧を、読み手への影響が大きい順に並べる。D8、D7、D9、D10 を先に直す。
3. 直す。内容は変えない。内容の整理が必要なら、`/sharpen doc` を勧める。
4. 直した規則の ID と、直さなかった規則の ID を、1行ずつ報告する。
5. HTML で、sharpen のリポジトリが手元にあるなら、`python3 scripts/check.py 成果物.html` を通す。
