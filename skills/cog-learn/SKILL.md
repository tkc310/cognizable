# cog-learn

読み手が詰まった箇所を特定し、約5分のレッスンで教える。レッスンの目的は、読み手が自分で判断できるようになること。

`cog-learn` が教える相手は、エージェントではなく人間の読み手。

## 使い方

```
/cog-learn
/cog-learn 話題
```

話題が書かれていないときは、直前の会話を読み、読み手が詰まった箇所を特定する。

## 出力には cognizable を適用する

始める前に、このスキルと同じ置き場にある `cognizable/SKILL.md` を読む。このスキルが出す文は、すべて `cognizable/SKILL.md` のルール R1〜R19 に従って書く。

`cognizable/SKILL.md` を読めないときは、読めないことを1行で読み手に伝える。そのうえで、次の5つを守って続ける。

1. 結論と次の行動を先頭に置く。
2. 読み手が覚えるか比べる項目は、4つまでにする。
3. 指示語を使わず、対象の名前をもう一度書く。
4. 主語と目的語を省略しない。
5. 前提から結論までの推論の段を飛ばさない。

このスキルが終わった後の応答は、`/cognizable` が有効なときだけ cognizable のルールに従う。

## 手順

1. 詰まった箇所を特定する。直前の会話から、読み手が「分からない」と答えた問い、同じ質問を繰り返した箇所、判断を保留した箇所を探す。
2. 特定した箇所を、1行で読み手に確かめる。例: 「これから教える内容: トークンをハッシュ化して保存する理由。内容が違えば、教えてほしい内容を返信してほしい。」
3. レッスンを3ステップで組み立てる。3ステップ目を読み終えた読み手が、詰まった箇所の判断を自分で下せるように、逆算して組み立てる。
4. 最初に、レッスンの地図を出す。地図には、3ステップの見出しと、所要時間（約5分）を書く。
5. ステップを1つ出す。ステップの最後に、確認の問いを1問出す。読み手の答えを待つ。
6. 読み手の答えに、下の「答えへの返し方」で返す。次のステップに進む。
7. 3ステップが終わったら、説明の問いを1問出す。
8. 下の「終わりの形」で締める。

1回の出力に入れるステップは1つだけにする。3ステップをまとめて出さない。

## ステップの形

ステップは、毎回次の順番で書く。

1. 位置: 「ステップ 2（全3ステップ）」の形で書く。
2. 見出し: ステップで読み手が得る結論を、文で書く。
3. 説明: 短い段落で書く。1段落は3文まで。段落は2つまで。
4. 実物: 手元のコードや資料から、説明に必要な箇所を引用する。引用は10行以内にする。引用には `パス:行番号` を付ける。
5. 対比: 読み手が知っている概念と比べる。何が同じで、どこが違うかを書く。
6. 確認の問い: 1問だけ出す。

1ステップは、2分以内で読める長さにする。

## 説明の決まり

- 一般論から始めない。読み手の手元のコードや資料にある実物から始める。
- 手元に実物がないときは、実物がないことを書く。そのうえで、最小の例を自分で作って示す。
- 新しい用語は、1ステップに2つまでにする。用語は、初めて出てきた文の中で定義する。
- 対比は、読み手が会話の中で使った語か、手元のコードにある概念から選ぶ。
- 前のステップの内容を使うときは、内容をもう一度1文で書く。「ステップ1で見たとおり」だけで済ませない。

## 確認の問いの決まり

- 確認の問いは、ステップの内容を当てはめて答える問いにする。用語の定義を答えさせる問いにしない。
- 確認の問いは、選択式にする。選択肢は3つにする。
- 選択肢の誤答は、よくある誤解に基づけて作る。明らかに違う選択肢を入れない。

確認の問いの例:

```
確認の問い: データベースの中身が外部に漏れた。招待トークンをハッシュ化して保存していた場合、攻撃者は招待リンクを作れるか。
A. 作れる。ハッシュから元のトークンを計算できるため。
B. 作れない。ハッシュから元のトークンを計算できないため。
C. 作れる。ハッシュをそのままリンクに入れれば通るため。
答え方: A、B、C のどれかを返信する。
```

## 答えへの返し方

1. 1行目に、正解か不正解かを書く。
2. 2行目に、正解の理由を1〜2文で書く。
3. 不正解のときは、読み手が選んだ選択肢のどこが違うかを1文で書く。責める言葉を使わない。
4. 続けて、次のステップを出す。

読み手が確認の問いに答えずに「次へ」と返信したときは、正解と理由を2行で書いて、次のステップに進む。

## 説明の問い

3ステップの後に、説明の問いを1問出す。説明の問いは、読み手が自分の言葉で答える問い。詰まっていた元の判断に、そのまま答えられる形にする。

例: 「招待トークンをハッシュ化して保存する理由を、2〜3文で説明してほしい。」

読み手の説明に対しては、合っている点を先に書く。次に、抜けている点か、ずれている点を1つだけ書く。

## 終わりの形

次の順番で書く。

1. 結果: 読み手が理解できた点を1〜2文で書く。
2. 提案: 次のどちらか1つだけを書く。
   - 読み手の説明にずれが残ったとき: 別の切り口でのレッスンを1つ提案する。
   - 読み手の説明が合っていたとき: 発展の話題を1つ提案する。
3. 次の一手: 1つだけ書く。詰まっていた元の判断があれば、「元の判断に戻る」を次の一手にする。

## してはいけないこと

- 読み手の理解を確かめずに、レッスンを最後まで出し切らない。
- 確認の問いを、1ステップに2問以上出さない。
- 読み手が頼んでいない話題へ、レッスンを広げない。

## 4つのスキルの流れ

| 順番 | スキル | 役割 |
|------|--------|------|
| 1 | `cog-plan` | 実装の計画を、成果物とプロセスの流れ図にする |
| 2 | `cog-ask` | 設計の問いを、1回に1問ずつ読み手に出す |
| 3 | `cog-learn` | 読み手が詰まった箇所を、約5分のレッスンで教える |
| 4 | `cog-review` | 変更の差分を、読む順番と説明を付けて案内する |

4つのスキルは、単独でも使える。
